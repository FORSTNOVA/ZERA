# ZERA

当前版本：**2.10.0**（2026-10-18）。主页面突出常用操作，辅助操作、日志、账号工具和设置采用右侧抽屉；支持 Esc、点击遮罩或关闭按钮返回。支持深浅主题，动效跟随 Windows 动画设置。
下载页的「更多操作」提供下载全部、获取直链与导出；任务页「更多」提供历史、诊断和记录清理。窗口底部持续显示最近消息，点击「查看日志」查看完整记录。设置页按下载与存储、分片与缓存、播放器分类，文本输入在回车或失去焦点时保存。
夸克、百度接入统一适配层，支持 WebDAV 通用接入。
新增 WebDAV：在「账号」页选择 WebDAV，再点击「接入 / 编辑 WebDAV」，填写连接名称、完整根地址、用户名和密码（可使用应用专用密码），测试通过后在「我的网盘」浏览和下载。匿名服务可留空账号密码。
支持 UTF-8 Basic / 匿名认证，HTTPS 有效证书；HTTP 需明确勾选允许未加密连接。不支持 OAuth / Digest / NTLM / SSO，不跟随重定向，需填写最终 WebDAV 地址。
凭据通过 DPAPI 加密保存，失败拒绝明文落盘。可记忆多个服务器/账号并切换；新任务绑定原账号，换到另一服务器后续传仍使用原账号。
WebDAV 不提供扫码、分享解析、上传或远端文件修改；分片与续传依赖服务器正确支持 Range。架构、用法和限制见 [统一适配层文档](docs/ADAPTERS.md)。
在「账号」页选择百度并登录，点击「Cookie / 会员查询…」再点击「百度会员 / 流量查询」，可重新读取当前账号的 VIP / SVIP 身份、接口提供的有效期和查询时间；显示最近一次原生取链响应的限速参数。
该入口只查询，不启动下载。当前已核实的会员接口**未提供剩余极速流量**，因此余额与是否已触发都明确显示无法确认，不把存储容量、线程数或缺少限速参数当作已启用加速的证据。
未知响应保持未知；失败不覆盖最后成功记录。真实会员识别后沿用既有会员并发建议，这不保证下载提速。余额仍需在官方客户端核对。
在「种子 / 磁力下载」窗口点击「Tracker 管理…」：
- 手动列表每行一条，支持 UDP / HTTP / HTTPS，也兼容逗号分隔列表；保存时校验格式。
- 订阅支持自定义名称、添加、编辑地址、启用/停用和删除；可一键添加 ngosang、XIU2 精选 GitHub 源。
- 支持 GitHub 具体文件页面（自动转换 raw 地址）、raw 原始地址及 HTTPS 纯文本地址，不支持仓库首页。
- 新增前点击「新建」，修改后点击「添加订阅」或「更新所选」，再「保存并关闭」。
- 「保存并立即更新订阅」保存当前列表并刷新所有已启用订阅；普通保存只使用现有缓存。
- 勾选「每天自动检查更新」后，在打开过 BT 窗口且程序仍运行时，每 15 分钟检查是否满 24 小时；失败后至少间隔 1 小时重试。关闭 BT 窗口仍可检查，退出程序停止。
- 名称、链接、启用状态、手动列表、成功时间和订阅缓存保存在配置同目录 `bt-state/trackers.json`；重启仍记忆。
- 获取失败、无有效 Tracker 或响应超过 1 MiB 时保留旧缓存；状态列显示结果。最多 20 个订阅、合并后最多 1024 条。
- 手动列表与启用订阅合并去重，保存/更新后用于新建的普通 BT、磁力和拆分任务，已有任务保留创建时的列表。
- 保留种子自带 Tracker。私有 `.torrent` 不追加公共列表；磁力获取元数据前无法判断私有标记，不应为私有资源使用公共发现方式。
- Tracker 用于发现节点，不保证提速；订阅更新是拉取地址列表，不代表每个 Tracker 都能从当前网络访问。

在「种子 / 磁力下载」窗口选择 **2 / 4 / 8 任务**，点击 **「拆分种子…」**，导入本地 `.torrent`。
种子块数不足时会相应减少子任务数。每个子任务使用独立 libtorrent 会话、连接和工作目录，
仅请求自己分配的不重叠块范围；每块校验通过后写入自己的紧凑分片。
子任务行可单独暂停和继续；选中 `[分组]` 行可暂停、继续或移除整组。
整组下载完成后自动再次核对原种子中的每块 SHA-1，按文件边界重建内容，
最后把完整结果发布到该任务目录下的 **`result/`**；不会覆盖不同内容的既有结果。
重启后整组保持暂停，点击继续会重新验证保存分片；损坏或缺失的块会重新获取。
合并中断保留分片，恢复后重新合并；移除整组保留文件，但不会自动重新关联。
拆分模式先支持本地 BT v1 种子（包括含 v1 信息的混合种子）；磁力链接继续使用普通模式。
同一时间最多启动一组拆分任务；先暂停整组才能切换到另一组。
普通与拆分模式分别限制总上传为 256 KiB/s，同时使用两种模式时上限合计 512 KiB/s。
拆分会增加连接、内存和磁盘开销，不保证比普通 BT 更快。
**磁盘按（子任务数 + 2）倍内容大小预留**，例如 4 任务预留约 6 倍空间；
支持稀疏文件的磁盘实际可能更少。分片及引擎工作文件会保留在任务目录。
拆分索引保存在配置同目录 `bt-state/split/`；任务内的 `job.json`、`source.torrent`、
`worker-*` 分片及位图是断点数据，请保留以便恢复。

点击下载页平台选择旁的「种子 / 磁力下载」，选择下载目录后打开 `.torrent` 文件，
或粘贴 `magnet:?xt=urn:btih:…` 链接并点击「添加磁力」。无需网盘账号，使用随包 aria2 引擎。
支持 BT v1（包括含 v1 信息的混合种子），暂不支持仅 BT v2 种子或仅 `btmh` 的磁力链接。
一次导入下载种子内的全部文件；当前不提供种子内文件勾选。
每个任务使用独立 `BT-…` 子目录，最多同时下载 2 个任务。
普通 BT 下载期间会向其他节点上传，该模式总上传上限为 256 KiB/s，完成后不继续做种。
速度受种源和网络影响；没有可用节点时可能持续等待，磁力链接需要先获取元数据。
BT 任务在独立窗口中暂停、继续和移除；网盘任务列表和托盘的暂停按钮仅控制网盘任务。
关闭 BT 窗口仍会下载，退出 ZERA 保存断点。重启后重新打开 BT 窗口，选中任务点击「继续」。
继续时会先读取种子和校验已下载数据，暂停状态下可能暂不显示历史进度。
移除任务不会删除文件；移除后重新导入会创建新目录。请保留原任务以便续传。
BT 会话保存在配置同目录的 `bt-state/`，文件旁的 `.aria2` 是续传控制文件，勿手动删除。
BT 引擎使用本机回环 RPC 与随机令牌，不向 BT 任务传递网盘 Cookie。

登录成功后自动记住本机账号；在「账号」页点击
「切换 / 管理账号」统一管理已保存的夸克、百度、WebDAV 账号。每行标注所属网盘；选中账号会先校验，成功后自动切换平台与账号，无需先手动切换平台。未登录时也可打开账号列表。
夸克、百度分别记住上次使用的账号，重启后自动校验登录；登录态过期需重新扫码或导入 Cookie。
切换成功会清空旧账号目录，网盘模式重新加载根目录；切换失败保留原账号。
目标平台有未结束的下载任务时，需先完成或取消任务再更换该平台账号；其他平台已有任务保留其客户端和分享刷新信息。登录校验失败时原平台与账号不变。
账号凭据沿用本机 DPAPI 存储方式，删除账号会清除相应本地档案及该平台记住的登录凭据；删除当前账号同时退出登录，有未结束任务的平台暂不允许删除账号。

> 一个 Windows 桌面端的**多平台网盘下载器** —— 支持**夸克网盘**与**百度网盘**的
> 分享链接 / 网盘直链解析、多线程分片下载、边下边播、多账号管理、深色模式。
> 基于 **.NET Framework 4.8 + WPF** 开发，**零 NuGet 依赖、可完全离线构建**。
> 界面为**星空主题**：深色是深空，浅色是晨曦天穹。

## ✨ 功能特性

### 支持的平台

| 平台       | 分享链接取直链 | 我的网盘 | 扫码登录         | 重启后手动确认续传    |
| -------- | ------- | ---- | ------------ | ------------ |
| **夸克网盘** | ✅       | ✅    | ✅            | ⚠️ 需保留完整取链信息 |
| **百度网盘** | ✅       | ✅    | ✅            | ⚠️ 仅「我的网盘」任务 |

> **关于百度网盘的两点说明**
>
> 1. **登录方式**：支持百度扫码登录；扫码不可用时，可从浏览器复制 Cookie 导入
>    （F12 → 网络 → 任一 `pan.baidu.com` 请求 → 请求头里的 Cookie，含 `BDUSS`）。
>    配置与账号档案中的 Cookie 正常情况下以 Windows DPAPI 加密保存；当前实现
>    在加密失败时会回退为明文保存。Cookie 会用于向对应网盘服务发送登录和下载请求。
> 2. **下载速度**：百度非会员账号受服务端限速，实际速度取决于账号权益及服务端策略。
>    程序对非会员账号每个下载任务使用 2 个并发连接，会员账号使用 32 个，
>    并在界面上显示相应说明；客户端不能保证突破账号限速。
>    百度下载默认每次请求不超过 **1 MiB**；这是网络请求范围，不改变原有分片与续传记录。

### 下载

- **两种写入方式**
  - `共写同一文件`：所有线程写同一个文件，**省磁盘空间**（默认）
  - `独立分片 + 顺序合并`：每个分片独立文件，**可边下边播**
- **高并发分片下载**：按文件大小与有效并发 ×32 规划分片，上限 16384；
  实际片数还受最小分片大小等条件约束
- **连接数按文件大小比例分配**：大文件多给连接，小文件不浪费
- **暂停 / 续传**：支持断点续传。重启后弹出未完成任务列表，默认不勾选；需勾选后
  点击「继续下载」，程序才会重新取链并接着下载。夸克分享任务需保留完整的取链信息，
  免转存或信息不全的任务可能无法续传；百度分享任务需重新解析链接，已转存为
  「我的网盘」任务的文件按网盘任务处理。
- **限速自适应**：被服务端限流时自动退避，空闲后自动恢复
- **百度小范围请求**：一个逻辑分片可由多次有界请求完成，旧任务继续使用原断点；
  日志仍显示原来的分片数和分片大小，同时单独显示请求上限
- **取消即清理**：取消任务后后台清理本地残留，文件被占用时会重试并记录结果
  （想保留进度请用「暂停」）

### 解析与登录

- **分享链接解析**：支持夸克分享链接（含带口令的链接）
- **免转存直链**：文件右键可选「免转存下载」，不占用网盘空间
- **二维码识别**：分享页只给二维码图片时，可在二维码识别窗口中粘贴图片（Ctrl+V）、
  选择图片文件，或拖入图片文件进行识别
- **扫码登录**：夸克与百度均支持。夸克使用内置 Python 桥换取登录态及获取账号信息；
  百度使用 .NET HTTP 客户端完成扫码登录，无需 Python 桥
- **多账号**：可保存多个账号，一键切换

### 体验

- **边下边播**：未下完也能用 VLC 播放已下载部分
- **星空主题**：深色 = 深空，浅色 = 晨曦天穹；背景是程序化生成的无缝星空贴图
- **深色模式**：亮色 / 深色 / 跟随系统
- **托盘常驻 + 悬浮小窗**：关掉主窗口也继续下载
- **导出直链**：纯直链 / curl / aria2c / Motrix 界面四种格式
- **拖拽识别二维码**：仅二维码识别窗口支持拖入图片；主窗口未实现拖入链接或文件添加下载任务

## 🚀 使用

### 方式一：下载发行版（推荐）

1. 从 [Releases](https://github.com/FORSTNOVA/ZERA/releases) 下载 `ZERA-v2.10.0-win64-20261018.zip` 并解压到任意目录
2. 双击 `ZERA.exe` 即可运行
3. 若系统缺少 .NET Framework 4.8，Windows 会弹窗提示，按引导安装即可

> 无需安装 Python —— 运行所需的精简 CPython 已内置于 `Runtime/` 目录。

### 方式二：从源码构建

```bash
# 1. 克隆仓库
git clone <仓库地址>
cd ZERA

# 2. 构建（Release）
dotnet build ZERA.slnx -c Release

# 3. 运行
src/ZERA/bin/Release/net48/ZERA.exe
```

构建前需安装支持 `.slnx` 的 **.NET SDK / MSBuild** 和 **.NET Framework 4.8 开发包**；
仅安装 .NET 运行时不能执行 `dotnet build`。本项目零 NuGet 包依赖，第三方库以固化 DLL
形式随仓库分发；`dotnet build` 会执行必要的项目还原，无需单独执行 `nuget restore`。

### 改名提示

本项目经历过两次改名：**鸽子下载 / GeZi → ZEKR → ZERA**（当前名）。程序会自动把老的
`GeZi.config.xml` / `GeZi.state.json`（以及 ZEKR 前缀的对应文件）**复制**一份为
ZERA 前缀的新文件（原文件保留，方便回退），因此升级后设置与下载历史不会丢失。

## 🧱 项目结构

```
ZERA/
├── src/
│   ├── ZERA/                     # 主程序（WPF 界面层）
│   │   ├── MainWindow.xaml(.cs)  # 主窗口
│   │   ├── ThemeManager.cs       # 亮/暗主题切换（三层资源字典原位替换）
│   │   └── Resources/            # 主题色、样式、图标、星空贴图
│   │       ├── Colors.Light.xaml # 亮色配色「晨曦天穹」（36 个键）
│   │       ├── Colors.Dark.xaml  # 深色配色「深空」（与亮色键一一对应）
│   │       ├── Brushes.xaml      # 画刷层：引用 Color，换肤时整层重挂
│   │       ├── Starfield.Light.xaml # 星空背景层（覆盖 AppBg/Sidebar 两个键）
│   │       ├── Starfield.Dark.xaml
│   │       └── ...
│   └── ZERA.Core/                # 核心逻辑（无 UI 依赖，可单独复用）
│       ├── Api/                  # 各网盘客户端（QuarkClient / BaiduClient）
│       ├── Panels/               # 平台抽象：IPanelClient 接口 + PanelKind 枚举 + 工厂
│       ├── Download/             # 分片下载引擎（与网盘平台无关，3143 行）
│       ├── Support/              # 会话层、链接解析、加密等
│       ├── lib/ZXing/            # 固化的 ZXing DLL（二维码解码）
│       └── Runtime/win-x64/      # 内置精简 CPython（夸克扫码登录用）
├── .assets/gen.py                # 星空贴图 / 图标的程序化生成脚本（PIL）
├── LICENSE                       # GPL-3.0
└── THIRD-PARTY-NOTICES.md        # 第三方组件声明
```

> **主题为什么是三层字典**：`Colors` 只放颜色，`Brushes` 引用它们，
> `Starfield` 再覆盖两个背景画刷为星空贴图。WPF 的 MergedDictionaries 是
> "后定义的键赢"，所以 `Starfield` 必须排在 `Brushes` 之后；
> 换肤时 `ThemeManager` 先换 Colors、再重挂 Brushes、最后换 Starfield。

> **多平台为什么不用插件化**：通用网盘操作通过 `IPanelClient` 和 `PanelRegistry`
> 复用；新增平台仍需接入界面入口、登录及平台专属流程。当前**没有做成动态插件加载** —— 本项目硬约束
> 「零 NuGet 依赖」，而插件化要么引 MEF/反射扫描，要么自己实现程序集加载与版本兼容，
> 复杂度远大于收益。

### 关于迅雷

本项目**没有**接入迅雷，原因是不可行而非未实现：

- 迅雷的老开放下载 SDK（`xldl.dll` / ThunderSDK）**已被官方删除**，
  网上流传的均为个人镜像；二进制再分发存在法律风险，且依赖已不存在的服务端。
- 新版开放平台 `open-xunlei.com` 需**企业资质申请**，个人拿不到。
- 迅雷云盘本身是存储产品，**没有"分享链接换直链"的能力**。

如需迅雷加速，唯一合法路径是通过商务渠道申请官方 SDK。
